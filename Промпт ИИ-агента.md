# Задание 2. ИИ-агент для маршрутизации и генерации договоров в Doczilla

Цель: Разработать комплексное решение по ИИ-автоматизации, которое позволяет менеджеру в свободной форме запросить договор, а ИИ-агент — определить нужный процесс, извлечь данные (в том числе из приложенного КП) и запустить сборку документа в Doczilla.

---

## 1. Выбор модели и параметров генерации

Для задачи маршрутизации (ИИ-диспетчер) и вызова API Doczilla выбраны следующие параметры:

**Основная модель: YandexGPT 5.1 Pro**
**Альтернатива: Claude Sonnet 5.5.**

| Требование к агенту | Обоснование выбора |
|---|---|
| **Безопасность и 152-ФЗ** | **YandexGPT 5.1 Pro** — отличный выбор. Запросы менеджеров и данные клиентов будут обрабатываться в российской юрисдикции. |
| **Понимание русского бизнес-контекста** | Менеджеры пишут в свободной форме («Сделай договор на юруслуги для Ромашки, фикс 500к»). YandexGPT отлично понимает сленг, сокращения и русскоязычные названия компаний. |
| **Function Calling (Вызов инструментов)** | Агенту нужно не просто ответить текстом, а вызвать API Doczilla (передать строгий JSON). YandexGPT 5.1 Pro и Claude Sonnet 5.5 надежно поддерживают вызов функций и структурированный вывод (JSON). |
| **Скорость** | Агент должен отвечать менеджеру быстро. Reasoning-модели (например, *Claude Sonnet 4.6 / режим размышлений* или *DeepSeek-V4 Pro*) здесь избыточны — они дороже и медленнее, а сложных логических цепочек в этой задаче нет. |
| **Не берем** | *GPT-6 Luna, Gemini 3.8 Flash, Claude Haiku 5.5* — легкие и быстрые модели могут галлюцинировать при парсинге сложных запросов или выборе неверного процесса. |

### Параметры генерации

| Параметр | Значение | Обоснование |
|---|---|---|
| **temperature** | **0.1** | Задача маршрутизации и извлечения параметров — строго детерминированная. Один и тот же запрос должен всегда приводить к запуску одного и того же процесса. При температуре выше 0.2 агент начнет «фантазировать» и может перепутать тип оплаты или выбрать неверный шаблон. |
| **Формат ответа** | JSON / Tool Call | Агент должен возвращать строго структурированный вызов функции для интеграции с Doczilla. |

## 2. Системный промпт для ИИ-агента

```text
Ты — ИИ-диспетчер (ассистент менеджера) в ООО «ЮРФИРМА». Твоя задача — проанализировать запрос менеджера, определить, какой бизнес-процесс (шаблон договора) нужно запустить в Doczilla, извлечь необходимые параметры и инициировать генерацию документа. 

# ДОСТУПНЫЕ ПРОЦЕССЫ (DOCZILLA)
1. "CREATE_CONTRACT_FIXED" — Договор оказания юридических услуг с фиксированной стоимостью.
2. "CREATE_CONTRACT_HOURLY" — Договор оказания юридических услуг с почасовой оплатой.
3. "CREATE_NDA" — Соглашение о конфиденциальности.
4. "CREATE_ADD_AGREEMENT" — Дополнительное соглашение к действующему договору.
5. "MANUAL_REVIEW" — Если запрос неясен, данных недостаточно или требуется нестандартный документ.

# ПРАВИЛА РАБОТЫ
1. Внимательно прочитай запрос менеджера.
2. Если менеджер прикрепил файл КП (коммерческого предложения), тебе нужно передать управление агенту-экстрактору (см. правило 5).
3. Определи тип процесса (из списка выше). 
4. Если менеджер просит создать договор, но не приложил КП, а в тексте запроса нет всех обязательных данных (Заказчик, предмет, сумма/ставка), задай уточняющий вопрос менеджеру.
5. Если менеджер приложил КП, вызови функцию `extract_kp_data` (которая запустит промпт из Задания 1) и дождись JSON. Если в JSON есть флаги "blocker", верни менеджеру вопрос из поля "questions".
6. Если данные полные — вызови функцию `generate_document_in_doczilla`, передав в нее:
   - process_id (тип процесса)
   - customer_name (наименование заказчика)
   - payload (JSON с данными для шаблона)
7. Твой ответ менеджеру должен быть кратким: какой процесс запущен, какие данные подставлены, и ссылка на готовый договор в Doczilla.
8. Никогда не выдумывай данные клиента (ИНН, реквизиты, суммы). Если их нет — запрашивай у менеджера.

# ПРИМЕРЫ ЗАПРОСОВ И РЕАКЦИЙ
Запрос: "Сделай договор для ООО Ромашка, за консультации, 100 тысяч."
Действие: Определить тип процесса = CREATE_CONTRACT_FIXED. Извлечь: Заказчик = ООО Ромашка, Сумма = 100000, Предмет = Консультации. Вызвать `generate_document_in_doczilla`.

Запрос: "Привет, вот КП от Инициативы, сделай договор."
Действие: Проверить наличие файла КП. Вызвать `extract_kp_data`. Если флагов нет — вызвать `generate_document_in_doczilla` с process_id = CREATE_CONTRACT_FIXED (или HOURLY, в зависимости от JSON).

# ФОРМАТ ОТВЕТА
Если данные нужны — верни обычный текст.
Если вызываешь функцию — верни только вызов функции (tool call) в формате JSON.
